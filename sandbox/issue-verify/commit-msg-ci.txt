fix(ci): 推 tag 不再跳过打包，发布正文不再被硬折行切成碎片

两件事都来自 v0.5.0/v0.5.1 发布当场的实测，不是推断。

1) build.yml 的 github.ref_type 判据写成复数 'tags'。GitHub 只有 branch / tag 两个取值，
   于是推 tag 时「Build release package」和「Upload release artifacts」两步整体跳过，
   下游 release job 下载产物时报 Artifact not found for name: dsh-launcher-windows。
   v0.5.0 的 tag run 就是这么红的（当时靠 gh workflow run --ref v0.5.0 走 dispatch 绕行），
   v0.5.1 同。两处一起改成单数：只改一处会变成「打了包没人上传」，同样是红。

2) 发布正文换行归一。CHANGELOG 每行约 100 列硬折行，而 GitHub 的 Release 正文把单个换行
   渲染成硬换行（v0.5.1 正文实测 26 个 <br>），公告因此看着被强行截断、右边大片留白。
   新增 scripts/release-notes.ps1 作为正文生成的唯一实现（抽版本小节 → 段内续行接回一行 →
   拼校验和与安装说明），build.yml 改为调用它，本地重发也调它——不抄第二份。
   相接规则：接缝两侧都是 ASCII 词字符才补空格，否则直接相接（中文相接不带空格，
   英文单词之间必须带）；空行/标题/列表项/表格/引用块/代码围栏一律原样。
   发布闸门 missing-changelog + exit 1 的字面量仍留在 build.yml 里（test.ps1 按文本断言盯它）。

重发两份公告后实测：v0.5.1 正文 <br> 26 → 1（剩下那个是双语安装说明里显式写的），
v0.5.0 → 7；按「忽略空白后逐字符相等」校验一字未丢（0.5.0 段 523 行 → 131 行，26701 字符不变）。
推送判据复核：v0.5.0 正文仍含 3 处 SECURITY（继续作为安全更新提示），v0.5.1 仍 0 处（不发推送）。

G7 棘轮 4 → 22：用户在两条出路（抬数 / 定版 v0.5.2 搬段）里显式选了抬数——0.5.2 的 MSI 与 ZIP
会和 0.5.1 逐字节相同，白发布一次。仍按「钉当下实测值、余量 +0」执行，授权来源写进闸的沿革注释。
抬之前它真的红过（[FAIL] ≤ 4 行（实测 22）），这道闸还在工作。

验证：scripts/test.ps1 全量 1366 例 + 580 条静态断言全绿（抬数后复跑）。
