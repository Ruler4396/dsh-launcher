## 用户需求

点击更新时弹窗报错 `[E4001] dsh 0.1.0-rc.7 下载失败。原因：文件名、目录名或卷标语法不正确`。用户明确要求：**先定位根因再修改，不盲目修改**。

## 根因（已本地实测复现确认）

`DownloadDshUpdateStaged`（Program.cs:1525-1535）在 `npm pack` 前只执行了 `Directory.CreateDirectory(staging)`，**从未创建 `prefetch_temp` 子目录**。`npm pack --pack-destination "C:\...\staging\prefetch_temp"` 指向不存在的目录时，Windows 中文系统底层 fs 返回本地化错误 ERROR_INVALID_NAME（"文件名、目录名或卷标语法不正确"），经 cmd/npm stderr 进入 errorTail 并在弹窗中展示。

本地复现验证：cmd.exe /c 执行 pack 到不存在目录 → EXIT=1，stderr 为该中文错误；pack 到已存在目录 → 正常。排除 cmd 引号、npm 路径等其他因素。

## 修复范围

1. 根因修复：pack 前创建 `prefetch_temp` 目录。
2. 编码加固：`RunNpmCommand` 设置 stderr/stdout 编码为 UTF-8，避免中文系统 GBK 输出乱码导致错误不可读。
3. 契约测试与 CI 静态断言：锁定"预热目录先创建"与"编码显式设置"两个行为。
4. 构建并更新 release 资产。

## 技术方案

### 根因修复（核心，Program.cs `DownloadDshUpdateStaged`）

在现有 `Directory.CreateDirectory(staging)` 之后补充创建 `prefetchDir`：

```
var staging = Path.Combine(DataDir, "staging");
var prefetchDir = Path.Combine(staging, "prefetch_temp");
Directory.CreateDirectory(staging);
Directory.CreateDirectory(prefetchDir); // 根因修复：pack 目标目录必须先存在
```

后续步骤（pack → 预热 install → 移动 tarball → 清理 deps）保持不变，无需改动——预热 install 已传 `workingDirectory: prefetchDir`（22:02 版已含）。

### 编码加固（Program.cs `RunNpmCommand`）

当前 ProcessStartInfo 未设 `StandardOutputEncoding`/`StandardErrorEncoding`，Windows 中文系统 cmd/npm 输出 GBK，默认 UTF-8 解码会乱码（本地实测 stderr 为 `�ļ�����Ŀ¼...`）。补：

```
StandardOutputEncoding = System.Text.Encoding.UTF8,
StandardErrorEncoding = System.Text.Encoding.UTF8,
```

确保 errorTail 与 progress 转发的 npm 输出在任何系统代码页下都可读，满足架构铁律"异常透明：用户能通过日志/弹窗看到真实失败原因"。

### 防御性校验（保持现状即可）

- pack 后已有 `File.Exists(tarballPath)` 守卫（1557/1564 行），tarball 未生成时跳过预热直接进入降级路径。
- pack 失败分支已有 errorTail 暴露 + 错误类型区分文案（IsNpmNotFoundError），符合铁律。

### 测试与 CI

- 新增/扩展 `UpdateFlowContractTests`：锁定 `StagedUpdate.PrefetchTempDir` 语义不变 + 新增静态契约（见下）。
- `test.ps1` 补静态断言：`DownloadDshUpdateStaged` 含 `Directory.CreateDirectory(prefetchDir)`；`RunNpmCommand` 含 `StandardErrorEncoding`。

### 性能与影响面

- 零性能开销（仅多一次目录创建）。
- 影响面收敛在下载管线与进程输出编码，不触碰状态机、UI、其他 Manager。
- 不引入新依赖、不改接口签名（RunNpmCommand 参数已兼容）。

### 风险与回退

- 若用户环境存在"目录被占用"等极端情况，`Directory.CreateDirectory` 已幂等且 DirectoryNotFound 会进外层 catch（E4001 + errorTail），不会崩溃。
- 编码统一为 UTF-8 可能改变部分环境（原 GBK 恰好可读）的输出外观，但保证语义正确、可读，属净改进。
