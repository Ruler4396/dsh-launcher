## 1. 修复清单（按风险级）

### P1 —— 确定性缺陷（建议本轮全修）
| # | 缺陷 | 来源 | 修复方向（克制版） | 用户感知 |

## 2. 已确认的无 P0 级缺陷

四份深度审计均未发现"数据损坏/权限提升/静默多驻服务"级 P0。最高级别为 P1（上述 8 项）。

## 3. 产品语义待拍板（影响修复实现）

1. **P1-6 pending 永续**：服务健康时检测到"已下载待应用"更新——气泡提示 vs 仅日志+文档说明 vs 提供"立即重启应用"按钮。
2. **外部托管服务关窗语义**（A4 R7）：`DSH_WEB_URL` 外部托管 + "跟随窗口"关窗——现状"只停壳拉起的服务"（绝不碰外部服务），意味着外部托管下常驻服务残留。是否保持保守（推荐）或加提示。
3. **P1-3 崩溃循环上限的兜底**：达上限后停止自愈（用户需重开/托盘唤窗恢复）vs 仅告警不停止（先观测）。
4. **修复范围**：P1 全修（8 项）+ P2 全做（10 项） vs P1 全修 + P2 仅死码清理（P2-1/P2-2）。

## 4. 不变量回归防线（来自 testing-governance.md R01–R15）

单实例唯一 / 无孤儿 node / 配置损坏可恢复 / 插件卸载不死锁 / 窗口位置不丢 / 日志不撑盘 / 更新失败保旧版 / 异常不静默 / 资源不泄漏 / UI 不假死——每条均有对应测试方向与现有防线映射（详见 testing-governance.md）。
